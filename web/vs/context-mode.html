SuperCompress vs context-mode

Short answer: context-mode is sandboxed tool output plus session memory. Where it runs: Locally, as a plugin, MCP server and hooks. SuperCompress is hosted, query-aware compression that keeps the original lines answering the current question. Pick context-mode if you live in Claude Code and want sandboxed tool output with session memory and dashboards. Pick SuperCompress if your agent keeps pulling big tool results, logs or retrieved docs and only a few lines matter for the question at hand, and you want those lines kept verbatim.

context-mode

A. context-mode

Best if you live in Claude Code and want sandboxed tool output with session memory and dashboards.

An MCP server plus hooks that sandboxes tool output, persists session memory and routes tool use, with Claude Code as its primary home. Licensed under the Elastic License 2.0 (source-available).

  • How it works: Sandboxed tool output plus session memory
  • Runs: Locally, as a plugin, MCP server and hooks
  • Setup: Install from the Claude Code plugin marketplace or npm
  • Licence: Elastic License 2.0 (source-available)

Strengths:

  • Keeps raw tool output out of the window
  • Session memory and checkpoints
  • Rich visibility

Limitations:

  • ELv2 is source-available, not open source; you may not offer it as a hosted service
  • Deepest support is for Claude Code
  • More behaviour to learn than a single tool

SuperCompress

B. SuperCompress (our product)

Best if your agent keeps pulling big tool results, logs or retrieved docs and only a few lines matter for the question at hand, and you want those lines kept verbatim.

Hosted, query-aware context compression. Your agent or app sends a bulky block (tool output, a log, a diff, a file read, an MCP result, retrieved docs) with the current question, and the hosted Neural Keep model keeps the original lines that answer it, word for word, and drops the rest.

  • How it works: Query-aware extraction of original lines
  • Runs: Hosted API, plus an MCP tool and hooks for coding agents
  • Setup: npm install -g supercompress-proxy && supercompress setup
  • Licence: Hosted service

Strengths:

  • Keeps original lines verbatim, so error messages, paths, IDs and code survive exactly
  • Query-aware: what is kept depends on the current question, not only on the content type
  • One setup command wires an MCP tool into each detected coding agent (Claude Code, Cursor, Codex, Windsurf, Cline, Gemini CLI, OpenCode and more), plus hooks where supported
  • HTTP API returns original_tokens and kept_tokens so you can measure on your own traffic
  • Works with any model provider because the output is plain text

Limitations:

  • Hosted: the context you compress is sent to the SuperCompress API
  • Compresses input only; it does not change how verbose model replies are
  • Not a code index or retrieval system; it shrinks what is already being sent

How to test any of these fairly

Every tool here, including ours, publishes its own numbers. Fewer tokens do not always mean a smaller bill once prompt caching, retries and extra agent turns are counted. Run the same tasks with and without a tool, check the tasks still succeed, and compare cost per finished task on your provider bill.

FAQ

Is SuperCompress better than context-mode?

They solve different parts of the problem. Best if you live in Claude Code and want sandboxed tool output with session memory and dashboards. Best if your agent keeps pulling big tool results, logs or retrieved docs and only a few lines matter for the question at hand, and you want those lines kept verbatim.

What is the main difference between SuperCompress and context-mode?

context-mode works on tool output and session state and runs locally, as a plugin, mcp server and hooks. SuperCompress works on input context and is hosted.

Can I use both?

Usually, if they act on different tokens. Measure cost per finished task with each on and off.
