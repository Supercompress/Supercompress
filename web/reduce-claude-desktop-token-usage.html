Reduce Claude Desktop Token Usage: Compress Long Context with MCP

Claude Desktop chats grow with pasted logs, long files, documentation and output from other MCP servers, and all of it rides along on every turn. Here is where those tokens go and what supercompress setup registers in claude_desktop_config.json so Claude can compress bulky context against the question you are asking.

By Arjun Shah · November 2, 2026 · Guide

In short: run npx supercompress-proxy setup or supercompress setup. Setup opens a browser sign-in link (no API key step), then adds a supercompress entry to the mcpServers map in claude_desktop_config.json on macOS and Windows, keeping your existing servers. Claude Desktop has no hooks, so nothing is compressed behind the scenes: Claude calls the compress_context tool when the conversation holds bulky text and works from the original lines that answer your question.

Where Claude Desktop tokens go

  • Pasted logs and stack traces. A crash log or CI output dropped into the chat stays in context for every later turn.
  • Long files and docs. Attached or pasted files ride along in full even when one section matters.
  • Output from other MCP servers. Results from servers such as filesystem or GitHub can be large, and they stay in the conversation after Claude has read them.
  • Long chats. Everything above the current message is resent each turn, and long conversations eventually hit the length limit.

How SuperCompress works

SuperCompress is hosted, extractive and query-aware. It keeps original lines chosen against the question and drops the rest. It never rewrites or summarizes, so file paths, error messages, IDs and code come back as they were. The question itself is never compressed.

In Claude Desktop the SuperCompress MCP server exposes compress_context, usage_summary, runway_check and connect_account. Every compress call reports original_tokens and kept_tokens, so you can see what was dropped on your own work.

What supercompress setup changes for Claude Desktop

supercompress setup and supercompress plugin write the same Claude Desktop file. Setup detects Claude Desktop on macOS and Windows, reads the existing config, keeps every mcpServers entry you already have and adds one supercompress entry next to them. No API key is written into the file: the MCP server reads the linked account from ~/.supercompress/config.json.

FileChange
~/Library/Application Support/Claude/claude_desktop_config.json (macOS)Adds mcpServers.supercompress: the installed SuperCompress MCP launcher as command, its args, and env.SUPERCOMPRESS_CONFIG_DIR pointing at ~/.supercompress. Existing mcpServers entries are kept.
%APPDATA%\Claude\claude_desktop_config.json (Windows)Same change: one supercompress entry is added to the mcpServers map and your own entries are kept.

That is the whole install. Claude Desktop has no hooks or instructions file, so unlike Claude Code there is no PostToolUse path that swaps output for you. The file shape matches the official MCP quickstart: Claude Desktop reads a mcpServers map of command, args and env from claude_desktop_config.json at those paths.

How a turn works

  1. You paste a long log, attach a file, or another MCP server returns a large result.
  2. Claude calls compress_context with the bulky text as context and your question as query. You can also ask for it directly: "compress this log against my question first".
  3. The tool returns the original lines that answer the question. The rest is dropped, and Claude continues from the smaller result.

Before large work, Claude can also call runway_check to see how much room is left, or usage_summary to report what has been compressed in the account.

Install

npx supercompress-proxy setup

If the CLI is already installed:

supercompress setup

Or install it first with npm i -g supercompress-proxy, then run supercompress setup. Setup opens a browser sign-in link. There is no API key step. It detects the agents on the machine and wires each one, including Claude Desktop on macOS and Windows. Then quit Claude Desktop fully and reopen it: it reads claude_desktop_config.json on launch, so a full restart is required before the SuperCompress tools appear.

Check what got wired

supercompress doctor

doctor prints a per-agent health check. For Claude Desktop the row shows MCP only, with no hooks or instructions columns filled in, because MCP registration is the whole Claude Desktop install. Before setup, doctor lists Claude Desktop under the agents that still need supercompress setup.

Wiring it by hand

If you prefer to edit the config yourself, add a supercompress entry to the mcpServers map in claude_desktop_config.json. With the CLI installed globally, the launcher bin is supercompress-mcp:

{
  "mcpServers": {
    "supercompress": {
      "command": "supercompress-mcp",
      "args": []
    }
  }
}

Keep your other mcpServers entries in place, then quit and restart Claude Desktop. Link the account once with supercompress setup or by letting Claude call connect_account.

Undo

supercompress uninstall

supercompress uninstall --yes skips the confirm prompt. Uninstall restores claude_desktop_config.json from the backup taken before the first write, so a config that held your own servers before setup goes back to exactly those servers. Restart Claude Desktop afterwards.

When to skip it

  • Short chats with small pastes. There is little to drop.
  • Text Claude must quote back in full, such as a document you are editing line by line.
  • Work where every byte must be passed through unchanged for compliance reasons.

FAQ

Does SuperCompress change my existing Claude Desktop MCP servers?

No. Setup reads claude_desktop_config.json, keeps every mcpServers entry you already have and adds one supercompress entry next to them. supercompress uninstall restores the file from the backup taken before the first write.

Does SuperCompress compress Claude Desktop messages automatically?

No. Claude Desktop has no hooks, so nothing is replaced behind the scenes. Claude calls compress_context when the conversation holds bulky text, such as pasted logs, long files or large output from other MCP servers, and works from the lines that come back.

Does SuperCompress rewrite or summarize what Claude reads?

No. It is extractive and query-aware. It keeps original lines chosen against the question and drops the rest. It never rewrites or summarizes, so file paths, error messages and code stay as they were.

Which operating systems does setup support for Claude Desktop?

macOS and Windows. Setup writes ~/Library/Application Support/Claude/claude_desktop_config.json on macOS and %APPDATA%\Claude\claude_desktop_config.json on Windows, the same files Claude Desktop reads for MCP servers.

How do I remove the Claude Desktop setup?

Run supercompress uninstall. It restores claude_desktop_config.json from the backup taken before the first write, so your own MCP servers are back exactly as they were. Quit and restart Claude Desktop afterwards.
