Reduce Zed Token Usage: Compress Tool Output in Zed's Agent Panel

Zed's Agent Panel grows with terminal output, file reads and large MCP tool results that stay in the thread. Here is where those tokens go and how SuperCompress lets the agent call compress_context so it keeps the original lines relevant to your question.

Then run npm install -g supercompress-proxy && supercompress setup (or supercompress plugin) to add a SuperCompress MCP server to Zed. Where Zed tokens go

  • Agent Panel thread. Terminal output, file reads and earlier tool results stay in the thread for later turns.
  • File reads. Whole files come back even when a few lines matter.
  • MCP tool results. Large results from other context servers stay in the thread.

Habits that cut Zed token usage for free

  1. Start a fresh Agent Panel thread per task. Old terminal output and MCP results stop riding along.
  2. Turn off MCP servers you do not use. In Settings > AI > MCP Servers, disable servers the current task does not need.
  3. Name the server when you want compression. Mentioning supercompress in the prompt helps the model pick the compress_context tool (Zed's MCP docs).
  4. Point at the files you mean. A named path is smaller than a broad search that dumps extra hits into the thread.

These habits shrink what goes in. They don't help when the agent genuinely needs to run a test suite or read a large file and only a few lines of the output matter. That is the part SuperCompress handles.

How SuperCompress works

SuperCompress is hosted, extractive and query-aware. Your agent sends a large block of context (a log, a diff, a file read, an MCP result) together with the question it is working on. It keeps the original lines relevant to that question and drops the rest. It never rewrites or summarizes, so file paths, error messages, IDs and code come back exactly as they were. The question itself is never compressed.

Every compress call reports original_tokens and kept_tokens, so you can see what was dropped on your own work instead of trusting a headline number. The usage_summary MCP tool shows totals per agent for your account.

What supercompress setup adds to Zed

Zed gets MCP only. There are no SuperCompress hooks and no instructions file. Setup writes Zed's user settings.json on macOS, Linux and Windows, keeps existing keys and other context servers, and sets agent.enable_all_context_servers to true.

WhatWhereWhat it does
MCP servercontext_servers.supercompress in Zed settings.json (command supercompress-mcp, env.SUPERCOMPRESS_CONFIG_DIR)Gives the agent the compress_context, usage_summary, runway_check and connect_account tools.
Agent flagagent.enable_all_context_servers: trueMakes context servers available to the agent.

Paths setup writes:

  • macOS: ~/Library/Application Support/Zed/settings.json
  • Linux: ~/.config/zed/settings.json
  • Windows: %APPDATA%\Zed\settings.json (AppData/Roaming/Zed)

Abridged shape of the block setup adds:

{
  "context_servers": {
    "supercompress": {
      "command": "supercompress-mcp",
      "args": [],
      "env": {
        "SUPERCOMPRESS_CONFIG_DIR": "<path>"
      }
    }
  },
  "agent": {
    "enable_all_context_servers": true
  }
}

Zed reads MCP servers from context_servers in settings.json. Zed's default tool permission prompts before MCP tool calls (agent.tool_permissions.default, confirm).

Install

npm install -g supercompress-proxy && supercompress setup

Or run supercompress plugin after the CLI is installed. Setup detects the coding agents on the machine and wires each one. Restart Zed so it loads the new MCP context server. Then check the server in Settings > AI > MCP Servers: a green dot means "Server is active". Confirm from the terminal too:

supercompress doctor
supercompress mcp-check

doctor prints a per-agent health check, including a Zed row. mcp-check verifies the MCP server responds. supercompress uninstall removes only the SuperCompress entry. Setup backs up each config file before it edits it.

Because Zed wiring is MCP only, ask the agent to call compress_context on a bulky dump (a log, a diff, a file read, an MCP result) together with the question it is working on. Mentioning the supercompress server by name in the prompt helps the model pick the tool.

When to skip it

  • Short sessions with small tool results. There is little to drop.
  • Files the agent is about to edit line by line. It needs those in full.
  • Work where every byte must be passed through unchanged for compliance reasons.

FAQ

Does SuperCompress change my other Zed settings or context servers?

No. It adds one context_servers.supercompress entry and sets agent.enable_all_context_servers to true. Existing keys and other context servers stay as they were.

Does SuperCompress compress every tool result in Zed automatically?

No. For Zed, SuperCompress wires MCP only: no hooks and no instructions file. The agent can call compress_context when output is large. Mentioning the supercompress server by name in the prompt helps the model pick the tool.

How do I undo the Zed setup?

Run supercompress uninstall. It removes only the supercompress entry from Zed settings.json. Your other settings and context servers stay as they were.
