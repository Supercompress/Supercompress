Caveman Cloud alternative: SuperCompress

Caveman Cloud is the hosted team product from the makers of Caveman: a console that shows what agent runs cost, suggests fixes and adds spend caps and governance. SuperCompress solves a narrower problem: it is a hosted API that shrinks each request by keeping only the original lines of bulky context that answer the current question. If you are looking for a hosted way to actually send fewer tokens, SuperCompress is the alternative to consider.

What Caveman Cloud is

According to caveman.so, Caveman Cloud is aimed at the company paying for the agents. It offers spend analytics split by agent and day, request traces, per-team usage, suggested improvements that are tested on past requests, evals, and governance features such as caps and rules for what may reach a model. It is a separate product from the free, open-source Caveman CLI. See the Caveman site for current plans.

Different jobs

Caveman Cloud is about seeing and governing agent spend across a team. SuperCompress is about the content of each request: when an agent or app is about to send a large log, file or tool result, SuperCompress cuts it down to the lines that matter for the question. Plenty of teams need the second without the first.

How SuperCompress works

SuperCompress is hosted, query-aware context compression. Your agent or app sends a bulky block of context (a log, a diff, a long file read, an MCP result, retrieved documents) together with the question being asked. The hosted API keeps the original lines that answer that question, word for word, and drops the rest. Nothing is paraphrased, so error messages, file paths, IDs and code come through exactly as they were.

Coding agents reach it through an MCP tool (compress_context) plus hooks that the setup command installs where the agent supports them. Apps reach it through POST /api/v1/compress, which returns the kept text along with original_tokens and kept_tokens so you can see what changed on your own traffic. See the benchmarks page for the published methodology.

How to pick fairly

Every tool in this space publishes its own headline numbers, and independent studies have found that fewer tokens do not always mean a smaller bill once prompt caching, retries and extra agent turns are counted. (see PointFive's end-to-end study, the code-compression-bench SWE-bench runs, JetBrains' rtk trial and the THOL leaderboard; none of them tested SuperCompress) Run the same tasks with and without a tool, check that the tasks still succeed, and compare your provider bill per finished task. That test matters more than any vendor page, including this one.

Try it

One command installs the CLI and wires the hosted compressor into every coding agent it finds on your machine (Claude Code, Cursor, Codex, Windsurf, Cline, Gemini CLI, OpenCode and more). Then supercompress doctor shows a health check per agent.

npm install -g supercompress-proxy && supercompress setup

Building your own app instead? Call the hosted API with a key from the dashboard.

FAQ

What is Caveman Cloud?

Caveman Cloud is the hosted team product from Caveman. It shows what agent runs cost, suggests and tests improvements, and adds caps and governance. It is separate from the open-source Caveman CLI.

What is a good Caveman Cloud alternative for reducing tokens?

If the goal is to send fewer input tokens per request, SuperCompress is a hosted option: it keeps only the original lines of bulky context that answer the current question.

Does SuperCompress replace a spend dashboard?

No. SuperCompress reports original and kept tokens for each compress call in your dashboard, but it is a compression service, not a team governance console.
