How to compress Firecrawl output before the LLM call

By Arjun Shah

Firecrawl turns a page into clean markdown and already removes headers, navs and footers by default. What is left is often still long, and most of it is unrelated to the question your app or agent is answering, so compress it against that question after scraping and before the model call.

Why is Firecrawl output still too big for one question?

Firecrawl's onlyMainContent option (boolean, default true) already strips headers, navs and footers before markdown is generated, and includeTags / excludeTags can filter HTML tags further. Those are the first, free trims to set on the Firecrawl side. What remains is still often the long main content of a docs, pricing or changelog page, most of which is unrelated to the one question your app or agent is asking. A crawl or batch scrape multiplies that volume, and agents often paste the whole result into the prompt and keep it in history.

Where does compression fit?

Scrape with onlyMainContent and tag filters, compress against the question, then call the model. Use one question per compression call. If one scrape answers several questions, compress once per question. Compression only removes text, so it cannot add facts the page lacks.

How do I compress Firecrawl markdown with the SuperCompress API?

curl -X POST https://www.supercompress.dev/api/v1/compress \
  -H "X-API-Key: $SUPERCOMPRESS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"context": "<Firecrawl markdown>", "query": "Which plan includes SSO?"}'
import os
import requests
from firecrawl import Firecrawl

firecrawl = Firecrawl(api_key="fc-YOUR-API-KEY")
doc = firecrawl.scrape("https://example.com/pricing", formats=["markdown"])
markdown = doc.markdown

question = "Which plan includes SSO?"
kept = markdown  # fail open: default to the original scrape
try:
    r = requests.post(
        "https://www.supercompress.dev/api/v1/compress",
        headers={"X-API-Key": os.environ["SUPERCOMPRESS_API_KEY"]},
        json={"context": markdown, "query": question},
        timeout=30,
    )
    r.raise_for_status()
    kept = r.json().get("compressed_text") or markdown
except requests.RequestException:
    pass

# Send kept to your model in place of the raw scrape.

SuperCompress is extractive and query-aware: it selects lines from the original rather than writing a summary, so text, URLs, numbers and code in the kept lines stay as written; preprocessing may rewrite JSON or collapse repeated stack frames before lines are chosen. Each response also reports original_tokens and kept_tokens, which are estimates, not provider-billed totals. When the saving would be too small the call passes through: compressed_text is the original and kept_tokens equals original_tokens.

How do I keep source URLs for citations?

Compress each page separately and prefix the kept text with its source URL (for example [source: https://example.com/pricing]) before joining pages, so the model can cite the page. Since kept lines are copied from the original, quoted text can be matched back to the page.

When should I skip compression?

  • Short pages, where there is little left to cut.
  • When you need the whole page, such as summarizing or translating it.
  • Structured extraction you already do with Firecrawl's JSON format.
  • If Firecrawl's own summary, question or highlights formats, or the excerpts that /search returns, already give you what you need, use those instead; compression is for when you need the page's original lines in the prompt.
  • When there is no specific question: the API then returns a broader digest labelled query_mode "dump".

For a fuller decision guide, see when to use prompt compression.

How do I know it helped?

  • Compare answers to the same questions with and without compression.
  • Log original_tokens and kept_tokens (estimates) per call.
  • Confirm on the provider bill. See whether context compression lowers your bill.

Frequently asked questions

Does this replace Firecrawl?

No. Firecrawl fetches and cleans the page. SuperCompress runs after scraping and before the model call, and trims the markdown against the question.

Isn't onlyMainContent enough?

It removes headers, navs and footers. It does not know your question, so long main content that is unrelated to the question still goes to the model. Use both.

Will compression change the scraped text?

SuperCompress selects original lines rather than writing a summary, so text in the kept lines stays as written. Preprocessing may rewrite JSON or collapse repeated stack frames before lines are chosen.

Do I need to send the question?

Yes, for a targeted result. Without a specific question the API returns a broader digest and labels the response query_mode "dump".
